# Git 常用命令与作用说明文档

这份文档记录了我们在开发“网页小游戏（贪吃蛇与拼图）”时，所学习和使用的 Git 核心命令。它可以作为你以后找实习、做项目时的快速参考手册。

## 📦 1. 基础工作流（每天都要用）

这是 Git 最核心的三步走流程：**写代码 -> 装箱 -> 封箱存档**。

*   **`git init`**
    *   **作用**：初始化 Git 仓库。
    *   **解释**：在当前文件夹里创建一个隐藏的 `.git` 文件夹，让 Git 开始监控这个目录里的所有文件。每个项目只需要运行一次。

*   **`git add .`**
    *   **作用**：将所有修改过的文件放入“暂存区”（装箱）。
    *   **解释**：告诉 Git，“我已经修改完代码了，把当前目录下所有的改动都准备好，一会儿我要一起存档”。这里的 `.` 代表当前目录下的所有文件。

*   **`git commit -m "你的备注信息"`**
    *   **作用**：正式提交存档（封箱并贴标签）。
    *   **解释**：把你刚才 `add` 进暂存区的文件永久保存在 Git 的本地数据库中。`-m` 后面的内容必须写，用于向未来的自己或同事解释“这次存档我具体做了什么修改”。

## 🔍 2. 查看状态与历史（了解当前进度）

*   **`git status`**
    *   **作用**：查看当前仓库的状态。
    *   **解释**：用来检查哪些文件被修改了但还没被 `add`（红色），哪些文件已经 `add` 准备好 `commit` 了（绿色）。

*   **`git log`** / **`git log --oneline`**
    *   **作用**：查看过去的提交记录（存档记录）。
    *   **解释**：能看到你每一次 `commit` 的哈希码（比如 `f2bfe7b`）、作者、时间和备注信息。加上 `--oneline` 可以让记录显示得更简洁。

*   **`git diff`**
    *   **作用**：查看代码的具体改动（找不同）。
    *   **解释**：在你运行 `git add` 之前，可以用它来看看你到底在文件里加了哪几行（绿色 `+`）、删了哪几行（红色 `-`）。（按 `q` 退出阅读模式）。

## ⏪ 3. 时光倒流（吃后悔药）

*   **`git restore <文件名>`**
    *   **作用**：撤销工作区未提交的修改。
    *   **解释**：如果代码写崩了，且**还没有 `git add` 和 `git commit`**，可以用这个命令把文件恢复到上一次存档的状态。

*   **`git reset --hard <哈希码>`**
    *   **作用**：强制回退到过去的某个指定版本。
    *   **解释**：让代码完全穿越回指定的存档点。注意：这会抹掉目标版本之后的所有修改，操作需谨慎。

*   **`git reflog`**
    *   **作用**：查看所有的操作日志（包括被隐藏的未来日志）。
    *   **解释**：如果你用 `git reset --hard` 回退后后悔了，想回到“未来”，可以用这个命令找到“未来”的哈希码，然后再用 `reset` 穿越回去。

---

## ☁️ 4. 远程协作（准备上传云端）

*   **`git config --global user.name "你的名字"`** / **`git config --global user.email "你的邮箱"`**
    *   **作用**：配置你的身份信息。
    *   **解释**：告诉 Git 你是谁。这是第一次安装 Git 时必须做的事情，以后提交的代码都会署上你的名字。

> **💡 总结：**
> Git 就像一个严谨的文件管家，它不关心你的代码写得好不好，它只负责精确地记录你的每一次改动，确保你的代码永远有迹可循、随时可以恢复。
